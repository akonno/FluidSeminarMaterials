# 計算結果を信用する前に

CFD計算が最後まで実行され、出力が得られたとしても、それだけで結果の妥当性が確認できたわけではない。このページではRe=1000のlid-driven cavity計算を例に、メッシュ解像度と計算終了時刻が結果に与える影響を確認する。

```{note} このページの位置づけ
ここでは、メッシュ解像度や計算終了時刻の影響を理解するため、通常の演習課題より詳しい比較・解析を行っています。**RMSEの計算、複数メッシュの系統比較、streamfunctionの重ね合わせ、中心線差分、`epsilon_U`の詳細な時系列評価を、授業課題のたびにすべて行うことを求めているわけではありません。**

課題では、明らかに粗すぎるメッシュや、流れが大きく変化している途中で計算を止めることを避け、結果に不自然な点がないか確認してください。ここでの詳しい解析は、なぜその確認が必要なのかを理解するための例です。具体的な条件や確認方法は、それぞれの課題の指示に従ってください。
```

## 「収束した」とは何か

「収束」には、少なくとも次の異なる意味がある。

1. **線形ソルバーの収束**：各時間刻みで、離散化された方程式を設定した許容残差まで解けたこと。
2. **時間発展の収束（定常状態）**：時間を進めても、速度場などの流れ場がほとんど変化しなくなったこと。
3. **格子収束（空間解像度）**：メッシュを細かくしたとき、注目する結果の変化が十分小さくなること。

各時間刻みの方程式を解けても、流れ場はまだ時間とともに変化していることがある。また、流れ場が定常になっても、粗いメッシュでは細かな流れ構造を表現できず、benchmarkとの差が残ることがある。この3つは別々に確認する必要がある。ここで示すメッシュ比較は解像度への感度を調べるものであり、最も細かいケースが完全に格子収束したことを証明するものではない。

## メッシュが粗くても定常にはなる

Re=1000のlid-driven cavityについて、16×16、32×32、64×64、128×128のメッシュを比較した。共通条件は次のとおりである。

```text
Re = 1000
U_lid = 1 m/s
L = 0.1 m
nu = 1.0e-4 m^2/s
```

4ケースとも、速度場の変化に基づく定常判定を満たした。一方、Ghia et al. (1982) のRe=1000中心線速度との誤差はメッシュによって異なり、細かいメッシュほど小さくなった。

```{figure} ./images/cavity/validation/mesh-streamfunction-comparison.svg
:alt: 16、32、64、128分割メッシュで再構成したstreamfunction contourの比較
:align: center
:width: 100%

メッシュごとのstreamfunction contour。16×16では下隅のsecondary vortexが検出されず、細分化したケースでは下隅の渦構造が現れる。空間解像度が不足すると、流れ構造の一部を表現できないことがある。
```

この図は、粗いメッシュで計算が定常になっても、細かな構造まで解像できるとは限らないことを示している。16×16では下隅のsecondary vortexが検出されず、32×32以上では両下隅に現れた。主渦の形状もメッシュ間で変化している。

| メッシュ | 定常開始 t* | 最終 epsilon_U | Ghia Re=1000 合成RMSE |
|---:|---:|---:|---:|
| 16×16 | 66 | 2.508e-5 | 0.10022 |
| 32×32 | 63 | 2.793e-5 | 0.04252 |
| 64×64 | 58 | 2.066e-5 | 0.01161 |
| 128×128 | 56 | 1.830e-5 | 0.00429 |

定常開始は、`epsilon_U < 1e-4`が5以上の無次元時間にわたり維持されたことを基準にした。表から、どのメッシュも定常基準を満たす一方、Ghia Re=1000との合成RMSEには差があることが分かる。合成RMSEは垂直中心線uと水平中心線vの参照点をまとめた値である。

```{figure} ./images/cavity/validation/mesh-centerline-u-comparison.svg
:alt: メッシュごとの垂直中心線速度uとGhia benchmarkの比較
:align: center
:width: 100%

メッシュを細分化すると、垂直中心線速度u(y)はGhia et al. (1982) のRe=1000データに近づく。図中にはRe=400のbenchmarkも比較用に示されているが、粗いメッシュのRe=1000計算がRe=400を再現するという意味ではない。
```

この比較では、格子を細分化するにつれてRe=1000の中心線速度が対応するbenchmarkへ近づく。粗いメッシュの計算結果を、別のReynolds数の解とみなすことはできない。この実験では「粗いRe=1000の計算はRe=400に近づく」という解釈は支持されなかった。

## セル数だけでなく、配置も重要

同じセル数でも、セルをどこに配置するかによって計算結果の精度は変わる。ここでは、同じRe=1000のlid-driven cavityについて、uniform 64×64、moderate graded 64×64、uniform 128×128の3つを比較する。

[![uniform 64×64、moderate graded 64×64、uniform 128×128の格子配置比較](./images/cavity/validation/nonuniform-mesh-comparison.svg)](./images/cavity/validation/nonuniform-mesh-comparison.svg)

*同じcavityに配置した3種類の格子。中央のmoderate格子はuniform 64×64と同じ4096セルを壁面近くへ再配分している。右のuniform 128×128は16384セルである。*

特にuniform 128×128は格子線が密なため、細部は図をクリックして拡大して確認してください。

uniform 64×64では、x方向とy方向のセル幅はどちらも一定で、`Δ/L = 0.015625`である。moderate 64×64ではセル数を増やさず、壁面近くを細かく、中央部を粗くした。壁際の最小幅は`Δ/L = 0.007184`、中央付近の最大幅は`Δ/L = 0.028737`である。

```{figure} ./images/cavity/validation/moderate-grading-detail.svg
:alt: moderate格子の全体と壁隅および中央付近のセル幅拡大図
:align: center
:width: 100%

moderate格子の全体図と拡大図。壁際のセルは細かく、中央付近のセルは広くなっている。
```

moderate格子の壁際の最小幅`0.007184 L`は、uniform 128×128の一定幅`0.007813 L`より少し小さい。一方、moderate格子の中央付近はuniform 128×128よりかなり粗い。4096セルを増やしたのではなく、必要と考えた場所へ配置し直した格子である。

moderate caseの`blockMeshDict`では、x方向とy方向に次のmulti-gradingを指定している。

```foam
simpleGrading
(
    ( (0.5 0.5 4) (0.5 0.5 0.25) )
    ( (0.5 0.5 4) (0.5 0.5 0.25) )
    1
)
```

各tripletは`(blockFraction nDivFraction expansionRatio)`を表す。x方向、y方向とも領域を半分ずつに分け、各半領域に64セルの半分である32セルを置く。壁から中央へセル幅が少しずつ大きくなり、中央から反対側の壁へ向かって小さくなる。

ここで`4`は隣り合うセルの幅を4倍にする指定ではない。最初の半領域で、壁側の端セルに対する中央側の端セルの幅の比を示す。32セルの間で幅を少しずつ広げ、中央側の端セルを壁側の端セルの約4倍にする。隣り合う幅の比はおよそ`4^(1/31) ≈ 1.046`である。

| 格子 | cells | min Δ/L | max Δ/L | Ghia RMSE（u / v / 合成） |
|---|---:|---:|---:|---:|
| uniform 64×64 | 4096 | 0.015625 | 0.015625 | 0.01143 / 0.01178 / 0.01161 |
| moderate graded 64×64 | 4096 | 0.007184 | 0.028737 | 0.002207 / 0.006780 / 0.005042 |
| uniform 128×128 | 16384 | 0.007813 | 0.007813 | 0.001780 / 0.005805 / 0.004293 |



moderate 64×64の合成RMSEは`0.005042`で、uniform 64×64の`0.01161`より約56.6%小さい。一方、uniform 128×128の`0.004293`より約17.4%大きく、同等とは言えない。この比較は格子配置による精度改善の一例であり、格子収束を証明するものではない。

壁面へセルを強く集中させれば、いつも全体の精度が上がるわけでもない。次の表では64×64のmild、moderate、strongを比較する。strongでは`u`のRMSEがmoderateより少し小さいが、`v`と合成RMSEは大きくなっている。

| 64×64格子 | Ghia RMSE（u / v / 合成） |
|---|---:|
| mild | 0.004998 / 0.006620 / 0.005866 |
| moderate | 0.002207 / 0.006780 / 0.005042 |
| strong | 0.001998 / 0.007638 / 0.005582 |

今回の計算では、uniform 64×64の`deltaT`は`3.90625e-4 s`、moderate 64×64では`1.25e-4 s`だった。観測されたmax Coはそれぞれ`0.222`と`0.120`である。壁際の最小セルが小さくなるとCourant数の制約が厳しくなり、`deltaT`を小さくする必要が生じる場合がある。ただし、必要な時間刻みは流れ場や局所セル幅などにもよる。この結果だけから、不等間隔格子では必ず同じ倍率で計算step数が増えるとは言えない。

## 各時間刻みで方程式が解けても定常とは限らない

次に、Re=1000、128×128メッシュの時間発展を調べる。まず、t*=80の定常場で選んだ**同じstreamfunction level**を、t*=5、20、80の各時刻に適用して比較する。

$$
\epsilon_U(t) = \frac{\lVert U(t)-U(t-0.1\,\mathrm{s})\rVert_2}{\lVert U(t)\rVert_2}
$$

この条件では0.1 sは無次元時間差`Delta t*=1`に相当する。後半では、この指標を使って定常状態を客観的に確認する。

### 見た目はもう定常に見える？

```{figure} ./images/cavity/validation/time-streamfunction-common-levels.svg
:alt: t*=5、20、80に同一のstreamfunction levelを適用した比較
:align: center
:width: 100%

各時刻にt*=80を基準とする共通のstreamfunction levelを適用した。線は、存在するlevelだけを示す。
```

この図では、t*=5では主渦の内側level 8本のうち3本だけが現れ、secondary vortex用levelは現れない。t*=20では主渦の内側levelが6本、左下のlevelが3本中1本、右下のlevelが4本すべて現れる。t*=80では、選んだ主渦・隅渦のlevelが成立している。存在するcontourはいずれも単一の閉曲線であり、開いたcontourはなかった。

したがって、t*=20ではcavityらしい流れに見えても、t*=80と同じψの値で比べると、同じ構造がまだすべて形成されているわけではないことが分かる。

### 本当に同じだろうか？

```{figure} ./images/cavity/validation/time-streamfunction-overlay-t20-t80.svg
:alt: t*=20の破線とt*=80の実線による共通streamfunction contourの重ね合わせ
:align: center
:width: 100%

全体図と主渦付近の拡大図で、破線はt*=20、実線はt*=80を示す。丸印と×印はそれぞれの主渦中心。
```

全体の形は似ていますが、主渦中心はt*=20の`(0.53906, 0.57031)`からt*=80の`(0.53125, 0.56250)`へ移動しています。移動量は`0.0110485 L`です。主渦の`psi*`は`-0.1135105`から`-0.1173889`へ変化し、t*=80で絶対値が約3.3%大きくなっています。差は極端に大きいわけではありませんが、見た目だけでは見落としやすい変化です。

### 差そのものを見る

```{figure} ./images/cavity/validation/time-centerline-difference.svg
:alt: t*=20と40の中心線速度差をt*=80の定常場と比較した図
:align: center
:width: 100%

t*=20および40について、定常場t*=80との差`Delta u = u(t*) - u(80)`、`Delta v = v(t*) - v(80)`を示す。横軸または縦軸の0が差のない位置。
```

表の中心線RMSEは、Ghiaの17個の座標に対応する位置でt*=80のprofileと比較した値である。t*=20では定常場との差がまだ明瞭ですが、t*=40ではかなり小さくなっています。それでもt*=40の`epsilon_U=4.133e-4`は、後述する定常判定基準をまだ満たしません。

| t* | `epsilon_U` | u RMSE vs t*=80 | v RMSE vs t*=80 |
|---:|---:|---:|---:|
| 5 | 0.22155297 | 0.17457 | 0.23509 |
| 20 | 0.01725719 | 0.0264758 | 0.0288154 |
| 40 | 0.0004132967 | 0.00105314 | 0.00121999 |
| 80 | 0.0000183027 | 0 | 0 |

t*=80は比較基準そのものなので、その時刻のRMSEは0です。t*=20から40にかけて差は大きく減りますが、「小さくなった」ことと「定常判定を満たした」ことは同じではありません。

### 定常性を客観指標で確認する

各時間刻み内で線形ソルバーが収束したことと、流れ全体が定常状態に達したことは別です。t*=5では速度・圧力の線形ソルバー残差は設定許容値内でしたが、`epsilon_U=0.2216`で、最終場との差も大きい状態でした。つまり、その時間刻みの離散方程式を解けても、流れの時間発展が終わったとは限りません。

ここでは`epsilon_U < 1e-4`を定常の目安とし、その状態が5以上の無次元時間にわたり維持されることを条件にします。

この数値と保持時間は、このページの比較に用いた具体的な判定基準です。すべての授業課題で同じ定量基準を一律に使うという意味ではありませんが、課題の指示に沿って定常性を確認することは大切です。

```{figure} ./images/cavity/validation/steady-epsilon-history.svg
:alt: 無次元時間に対する速度場変化指標epsilon Uの履歴と定常判定基準
:align: center
:width: 100%

速度場の相対変化指標epsilon_Uの時間履歴。水平線は定常判定の目安`epsilon_U = 1e-4`を示す。
```

`epsilon_U`はt*=56で初めて基準未満となり、その後t*=80まで基準内に留まりました。これが、この計算で定常性を判断する根拠です。見た目では判断しにくい変化を中心線差分で確かめ、最後に速度場全体の変化指標で定常状態を確認する、という順に見ることができます。

なお、Ghia benchmarkとの誤差が最小になった時刻を定常時刻とみなすこともできません。この実験ではt*=40の水平中心線vのGhia RMSEは0.00549で、t*=80の0.00580よりわずかに小さかったためです。benchmarkとの比較は空間的な解の妥当性を調べるものであり、時間的な定常性の判定とは目的が異なります。

## 時間に関する用語

- **時間刻み `deltaT`**：数値計算が時間方向に進む1ステップの幅。
- **計算終了時刻**：計算対象として指定したシミュレーション時間の終点。
- **無次元時間 `t*`**：ここでは`t* = t U_lid / L`。物理時間を代表速度と代表長さで無次元化した値。
- **実時間（wall-clock time）**：計算機上で計算を実行するのに要した時間。

このページで問題にしているのは、計算機上の実時間が短いことではなく、シミュレーションの計算終了時刻が早すぎて、流れが定常になる前に計算を止めてしまうことである。

## まとめ

CFDでは「計算が終わった」「残差が下がった」だけでは、結果の妥当性を確認したことにはならない。空間方向ではメッシュ解像度が十分か、時間方向では求める定常状態まで十分に時間発展したかを、それぞれ確認する。

線形ソルバーの収束、流れ場の定常状態、格子解像度への依存性は別の観点である。定常になったことと、十分な空間解像度で妥当な解が得られたことも区別しよう。

このページの詳細な解析は理解のための例です。通常の演習では、課題で指定された範囲でメッシュ解像度と定常性を確認してください。
